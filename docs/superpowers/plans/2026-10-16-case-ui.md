# Case UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A light, sidebar-based case UI matching the two reference images, every figure backed by real data.

**Architecture:** One read-only backend view module (`api/case_view.py`) turns a stored case, its investigation result, hold plan and actions into the overview payload and the STR Markdown. The frontend gets an app shell (sidebar + routes), a Case overview page made of small panels, and pure helpers (flow layout, stepper) tested with vitest. The 3D Workspace and HoldPanel are reused, not rewritten.

**Tech Stack:** FastAPI, pytest; React 19, TypeScript, Tailwind 4, recharts 3, lucide-react, vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-case-ui-design.md`

## Global Constraints
- Thresholds in `config.yaml` (`ui:` block), not in code.
- Overview and report endpoints are read-only; they run no Cypher writes.
- Amounts are USD in storage; display with `fmtMoney(usd, currency, rate)`. Never ₹ unless the data's currency is Rupee.
- No dead buttons; no search/date/bell/avatar/share/more/tour.
- Visible keyboard focus on every interactive element; works at 1280 px wide.
- Do not commit `data/models/*`, `data/processed/fx_rates.json`, `.gitignore`, `data/samples/eval/`, secrets. No attribution trailers. Don't push.

## Review Focus
- A case not yet investigated (no result, no plan): overview still renders case payments, roles, KPIs; findings say "not investigated yet". → test in Task 1.
- A pure cycle (every account sends and receives): all nodes Intermediary; layout terminates and places every node. → tests in Tasks 1 and 3.
- Mixed or missing currency on payments: falls back to the plan's currency, then US dollars. → test in Task 1.
- A hold account outside the case (downstream on the trail): appears in the flow, amber. → test in Task 1.
- Opening another case while one streams: the old stream's events never paint the new case. → guarded in Task 5 (stale flag), checked in verification.

### Task 1: Overview view model (backend)

**Files:** Create `backend/flowtrace/api/case_view.py`, `backend/tests/test_case_view.py`. Modify `config.yaml` (add `ui:`), `backend/flowtrace/pipeline/cases.py:116` (add `"cur": t["payment_currency"]` to case edges when present).

**Interfaces — Produces:**
- `confidence(weight: float, rules: dict) -> str` → "High" | "Medium" | "Low"
- `priority(score: float, rules: dict) -> str`
- `flow(case, result, plan, actions, rules) -> {"nodes": [...], "edges": [...], "payments": [...]}` — node `{id, role, amount, sent, received, in_case, hold: "proposed"|"approved"|None, entity_type}`; edge (one per src→dst pair) `{src, dst, amount, count, status: "flagged"|"trail"|"normal", hold: bool, first_ts, last_ts}`; payment `{tx_id, ts, src, dst, amount, fmt, status}` newest first.
- `timeline(payments) -> {"bucket": "hour"|"day", "bins": [{"t", "flagged", "other", "n"}]}`
- `build_overview(case, result, plan, actions, job, failed, rules) -> dict` keys: `case_id, batch_id, title, typology, description, priority, case_score, currency, rate, status, kpis, flow, timeline, distribution, findings, explanations, indicators, summary, next_steps, created_ts`.
- `status.state` ∈ `not_started | queued | investigating | failed | escalate | review | close`.

- [ ] Tests (fail first): `test_roles_from_flow` (A→B→C: Sender/Intermediary/Destination; amounts 100 sent / 90 received / 90 received), `test_pure_cycle_is_all_intermediaries`, `test_context_edges_excluded`, `test_flagged_vs_trail_status` (case payment flagged; trace payment not cited = trail; trace payment cited by support evidence = flagged), `test_hold_account_downstream_is_in_flow_and_amber`, `test_confidence_thresholds_from_config` (0.5 High, 0.35 Medium, 0.34 Low), `test_timeline_hourly_vs_daily`, `test_uninvestigated_case_renders` (status not_started, findings [], summary None), `test_currency_single_then_plan_then_usd`, `test_status_from_job_and_disposition`.

### Task 3: Frontend pure helpers + vitest

**Files:** `frontend/package.json` (vitest dev dep, `"test": "vitest run"`), create `frontend/src/lib/flowLayout.ts`, `frontend/src/lib/stepper.ts`, `frontend/src/lib/markdown.ts` with `*.test.ts` beside each.

- `layoutFlow(nodes: {id}[], edges: {src,dst}[], opts?) -> {pos: Record<id,{x,y,layer}>, width, height, back: Set<"src>dst">}` — break cycles by DFS back edges (start from sources, then remaining nodes in input order), longest-path layers, 2 barycenter passes for order, centre each layer vertically.

- [ ] Tests first: chain gets 3 layers; cycle terminates with all nodes placed and one back edge; fan-out puts 1 node in layer 0 and 5 in layer 1; stepper states for not-started / running / proposals open / all decided; markdown headings and bullets.
